# End-to-end test: Specialist Test for Another GLH

Test cases for the NW-GMSA IG scenario [Specialist Test for Another GLH](https://nw-gmsa.github.io/en/ExampleScenario-SpecialistTestForAnotherGLH.html). Great Ormond Street Hospital (`RP4`) orders a monogenic hearing loss test (R67.1) from North Thames GLH, which sends a sub-order through GOMS to the North West GLH (`699X0`, iGene) as the national provider for the test.

GOMS is **simulated** for now: the files under `GOMS/` are the FHIR payloads the RIE would get from, or send to, GOMS. The plan is to connect to the GOMS Int environment later. The files under `V2/` are the NW side (iGene to and from the RIE). All the fixtures are generated by `../build_glh_sub_order_scenarios.py`.

The North West GLH's report is sent to the central repository (NHS England Unified Genomic Record, UGR) as an `MDM^T02` with the report as a PDF. A FHIR Document may replace the PDF later.

## Running

- The v2 cases are registered in `IntegrationTest.py` as the `specialist_test_other_glh` group: `python3 IntegrationTest.py --group specialist_test_other_glh`.
- The `GOMS/` payloads are what a GOMS simulator should return (SPEC-02G) or accept (SPEC-03G to SPEC-04G). They are not run by `IntegrationTest.py`.

## Known gaps

- North Thames GLH's ODS code is taken to be `69A70`, "LONDON NORTH GENOMIC LABORATORY HUB (GLH)" in the NHS ODS directory. Check it against the GOMS onboarding details; to change it, set `NORTH_THAMES_GLH_ODS` in `../build_glh_sub_order_scenarios.py` and re-run it.
- Which specialist tests the North West GLH actually receives from other GLHs is not confirmed.
- The simulated GOMS base URL is `https://goms.simulated.example.nhs.uk/FHIR/R4` (`GOMS` in the script).
